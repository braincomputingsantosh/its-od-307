3.1

AI Algorithms & Models

"Choosing the wrong algorithm is like using a hammer to perform surgery — you have the wrong tool for the job."

An algorithm is the learning strategy — the method for finding patterns. A model is the result of running that algorithm on data — a trained artifact that can make predictions on new inputs. Before choosing any algorithm, you must first correctly identify what type of problem you are solving.

The Four Problem Types

🏷️
Classification
Output is a category. "Is this email spam or not?" "Is this tumor malignant or benign?" You have labeled training data.
📈
Regression
Output is a number. "What will this patient's blood pressure be?" "How much will this house sell for?" Labeled data with numeric targets.
🔍
Unsupervised Learning
No labels. The algorithm finds hidden patterns, groups, or anomalies on its own. "What natural customer segments exist in this data?"
🎮
Reinforcement Learning
The AI learns by trial and error with rewards and penalties. "What sequence of actions maximizes the long-term outcome?"

Decision Framework: Which Type Do You Have?

QuestionAnswerProblem Type
Do you have labeled data?Yes — labels are categoriesClassification
Do you have labeled data?Yes — labels are numbersRegression
Do you have labeled data?No labels at allUnsupervised
Can the AI try actions and get feedback?Yes — reward/penalty systemReinforcement

Algorithm Families

Supervised Learning Algorithms

Learning From Labeled Examples

  • Decision Trees: A flowchart of yes/no questions. Easy to explain: "Is credit score >650? → Is income >$50K? → Approve loan." Interpretable but can overfit.
  • Neural Networks: Layers of interconnected nodes inspired by the brain. Excellent for images and text; hard to interpret internally.
  • Random Forest: An ensemble of many decision trees that vote together — more robust than any single tree.
  • Logistic Regression: Despite the name, this is a classification algorithm. Outputs a probability (0–1) of belonging to a class. Highly interpretable.
Unsupervised Learning Algorithms

Finding Hidden Structure Without Labels

  • K-Means Clustering: Groups data into K clusters by finding the centers that minimize distance to all points in each group. Used for customer segmentation.
  • Anomaly Detection: Learns what "normal" looks like and flags records that deviate significantly. Used for fraud detection and equipment fault prediction.
  • Dimensionality Reduction (PCA): Compresses many features into fewer, more informative ones — useful for visualization and preprocessing.
Reinforcement Learning

Learning Through Reward and Penalty

  • Core idea: An agent takes actions in an environment, receives rewards or penalties, and gradually learns the strategy that maximizes cumulative reward over time.
  • Healthcare example: Optimizing treatment sequences for cancer — the AI tries different combinations and learns which sequences lead to the best patient outcomes.
  • Finance example: Dynamic pricing — the AI adjusts product prices based on customer responses and learns which pricing strategies maximize revenue.
  • Famous example: AlphaGo — learned to play Go at superhuman level purely through self-play and reward signals.

Real-World Applications

Section 3.1 — 5 Practice Questions

1. A hospital wants to predict the exact number of emergency room visits expected each day for the next month. Which type of AI problem is this?
✔ Correct Answer: B
Predicting a specific number (daily ER visit count) is a regression problem. The output is continuous and numeric. Classification would be used if the question were "will ER volume be high or low?" — but the question asks for the exact number.
Teacher note: C is a common distractor — there IS labeled historical data (past ER counts). Reinforce: the type of output (number vs. category) is the deciding factor.
2. A bank analyzes customer transaction history and discovers three natural groups of spending behavior without having defined those groups in advance. Which algorithm family was most likely used?
✔ Correct Answer: C
The key phrase is "without having defined those groups in advance." This is unsupervised learning — the algorithm discovered natural structure in unlabeled data. K-means clustering is the classic algorithm for this type of problem.
Teacher note: A is wrong because there are no predefined categories with labels. Students often confuse "grouping" with "classification" — the key difference is whether labels exist before training.
3. Which TWO of the following are characteristics of supervised learning? (Choose TWO)
✔ Correct Answers: A and C
Supervised learning requires labeled training data (A) and produces either categorical or numeric outputs (C). B describes unsupervised learning; D describes reinforcement learning.
Teacher note: D is a particularly important distractor — students often conflate "learning from feedback" with supervised learning. The distinction: supervised uses static labeled datasets; reinforcement uses dynamic environmental feedback.
4. An AI is being trained to find the optimal sequence of insulin dosing decisions for a diabetic patient over 24 hours, learning from the patient's physiological responses. What type of learning is this?
✔ Correct Answer: D
Sequential decision-making with environmental feedback is the hallmark of reinforcement learning. The AI must take actions (dosing decisions), observe outcomes (blood glucose response), and learn which action sequences lead to the best long-term result.
Teacher note: A is a common guess because dosing involves numbers. But the key is that this involves sequential decisions over time with feedback — not predicting a single value from a static dataset.
5. A team has customer purchase data but no predefined labels or categories. They want to understand natural patterns. Which approach should they take FIRST?
✔ Correct Answer: C
Without predefined categories and with a goal to "understand natural patterns," unsupervised clustering is the right first step. It lets the structure emerge from the data rather than imposing assumptions about what the groups should be.
Teacher note: B is tempting — many students suggest manually labeling data. But manual labeling introduces human bias about what segments should exist. Clustering first, then labeling the discovered groups, is the sound methodological approach.
3.2

Machine Learning Model Development

"Your first model is never your final model — iteration is the process, not a sign of failure."

Model development is an inherently cyclical process. You train, tune, measure, and iterate — repeatedly — until performance meets the real-world requirement. Understanding the four stages and what can go wrong at each one is essential for building reliable AI systems.

The Four-Stage Development Journey

01
Training with Best-Guess Parameters
Establish a baseline using domain knowledge and published defaults. This is not about getting perfect results — it's about getting something to measure and improve from.
02
Fine-Tuning (Hyperparameter Optimization)
Systematically adjust settings like learning rate, model depth, and regularization strength. Use grid search, random search, or Bayesian optimization to explore the parameter space.
03
Measuring Performance with Metrics
Evaluate the model on held-out data using appropriate metrics. Accuracy alone is rarely sufficient — you need precision, recall, and business-aligned KPIs.
04
Iteration — The Refinement Cycle
Based on evaluation insights, decide whether to adjust parameters, change the model architecture, collect better data, or engineer new features. Then repeat stages 1–3.

Overfitting vs. Underfitting

The Core Tension in Model Training Every model must find a balance: complex enough to learn real patterns, but not so complex that it memorizes the training data's noise. Overfitting is too much complexity; underfitting is too little.
ProblemWhat It Looks LikeWhat Causes ItHow to Fix It
Overfitting
"Memorization"		 Near-perfect training accuracy; poor test accuracy. Large gap between the two. Model too complex; too many features; not enough training data Regularization, simpler model, cross-validation, more training data
Underfitting
"Oversimplification"		 Poor accuracy on both training and test data. Model cannot learn the pattern. Model too simple; too few features; insufficient training epochs More complex model, feature engineering, longer training, domain knowledge

Domain-Specific Tuning Priorities

Healthcare Tuning Priorities

Pneumonia Detection from Chest X-Rays

  • Stage 1: Start with a proven convolutional neural network architecture. Learning rate 0.001, batch size 32, 50 epochs.
  • Stage 2: Tune toward high recall — missing a pneumonia case is far more dangerous than a false alarm.
  • Key consideration: Interpretability may be prioritized over marginal accuracy gains. Radiologists need to understand why the model flagged an image.
  • Stage 4 iteration: If model struggles with rare pneumonia types, collect more labeled examples of those edge cases.
Finance Tuning Priorities

Credit Card Fraud Detection

  • Stage 1: Random forest baseline. Initial result: 92% accuracy — but only caught 45% of actual fraud cases.
  • The trap: 92% accuracy sounds great. But with only 0.1% of transactions being fraudulent, a model that predicts "not fraud" for everything achieves 99.9% accuracy. Accuracy is misleading on imbalanced data.
  • Stage 2: Use cost-sensitive learning, adjust decision thresholds, implement resampling to balance the dataset.
  • Result after tuning: Fraud detection rate improved to 78% while keeping false positives under 2%.
Exam Practice

Section 3.2 — 5 Practice Questions

6. A fraud detection model achieves 99% accuracy on training data but only 60% on new transaction data. What is the MOST likely problem?
✔ Correct Answer: B
A large gap between training accuracy (99%) and test accuracy (60%) is the classic signature of overfitting. The model learned the specific patterns of the training transactions — including noise — rather than the general characteristics of fraud.
Teacher note: C is a plausible distractor. Data leakage would also produce artificially high training accuracy. The key distinction: data leakage tends to produce very high test accuracy too (since the answer was leaked). Overfitting produces high training, poor test.
7. In which stage of model development would you adjust the learning rate and regularization strength?
✔ Correct Answer: B
Learning rate and regularization are hyperparameters — high-level settings that control how the algorithm learns. Systematically adjusting these to improve performance is the definition of Stage 2: fine-tuning.
Teacher note: D is a common answer because "iteration" sounds like it includes everything. Clarify the distinction: Stage 4 is about deciding what strategy to change next based on evaluation; Stage 2 is the actual adjustment of parameters.
8. A medical AI predicts patient recovery time using only the patient's age, ignoring diagnosis, surgery type, and complications. It performs poorly on both training and test data. What is the problem?
✔ Correct Answer: B
Poor performance on BOTH training and test data (not just test data) is the signature of underfitting. The model is too simple — using only age ignores the most predictive variables. Fix: add more features and use a more complex model.
Teacher note: A and D both say overfitting — use this to reinforce the key diagnostic: overfitting = good training, poor test. Underfitting = poor both. The gap tells you which problem you have.
9. Which TWO statements are true about the model development iteration cycle? (Choose TWO)
✔ Correct Answers: A and C
Iteration is designed into the ML process — the first model establishes a baseline (A), and each iteration teaches the team something new about what works (C). B misframes iteration as failure. D sets an impossible and harmful target (100% accuracy almost always means overfitting).
Teacher note: D is worth discussing explicitly. 100% training accuracy is a red flag, not a goal. Use this to preview the overfitting concept.
10. A team wants to find the best hyperparameter combination for their model. They have limited time but a large parameter space. Which tuning approach is MOST efficient?
✔ Correct Answer: B
Random search is counterintuitively efficient because in large parameter spaces, not all parameters matter equally. Random sampling explores the space more broadly and often finds good solutions in a fraction of the time grid search requires.
Teacher note: A (grid search) is thorough but exponentially expensive as parameters increase. Use the city-map analogy: grid search checks every block; random search drops pins across the whole map and often hits the good areas faster.
3.3

Model Selection & Data Storytelling

"The best model is not always the most sophisticated one — it's the one that solves the problem reliably and can be trusted."

Two skills define the difference between a data scientist and a data scientist people trust: knowing how to choose the right model for the problem at hand, and knowing how to communicate what the model found in a way that drives real decisions.

The Over-Engineering Trap

More Complexity ≠ Better Results A hospital spent six months building a cutting-edge deep learning readmission predictor. The system was technically impressive. Doctors couldn't understand why it made its predictions. They didn't trust it. It was abandoned. A simpler logistic regression model — less accurate by 3% but fully explainable — was deployed instead and actually reduced readmissions.

Model Selection Criteria

🎯
Accuracy
How well does it solve the problem? But always check — is accuracy the right metric, or do you need precision/recall?
⚡
Speed
How fast is training and prediction? A model that takes 2 seconds per query cannot support real-time fraud detection.
🔍
Explainability
Can you explain decisions to regulators, doctors, or customers? In healthcare and finance, this is often non-negotiable.
🔧
Maintainability
How easy is it to update, retrain, and debug? Simpler models are easier to maintain as data evolves.

Explainability vs. Accuracy Trade-off

Model TypeAccuracyExplainabilityBest For
Logistic RegressionModerateVery High — exact coefficientsRegulated decisions (credit, clinical)
Decision TreeModerateHigh — readable flowchartRule-based business decisions
Random ForestHighMedium — feature importance availableGeneral prediction tasks
Gradient BoostingVery HighMedium — SHAP values neededCompetitive ML, tabular data
Deep Neural NetworkHighest (for images/text)Low — "black box"Images, audio, natural language

The Art of Data Storytelling

Raw numbers and accuracy scores don't move people to action. Stories do. A compelling data story follows a three-act structure:

🎬
Act 1: The Setup
Establish context and stakes. "Our hospital has seen readmissions rise 12% over 18 months. Each readmission costs $8,000 and harms patient outcomes."
⚔️
Act 2: The Conflict
Identify the specific problem your analysis addresses. "We needed to know: which patients are most at risk, and why? Surveys were insufficient."
💡
Act 3: The Resolution
Present findings with clear, honest visualizations and a specific call to action. Not just what you found — what should happen next.

3.5

Model Evaluation & Performance Assessment

"A model that's 99% accurate at predicting a disease affecting 1% of people might still be completely useless."

Evaluation is not a one-time activity — it is an ongoing obligation. Choosing the right metrics for the right problem is one of the most consequential decisions in AI development. The wrong metric can make a broken model look successful.

The Core Classification Metrics

Accuracy
"What % of all predictions were correct?"
Simple overall grade. Misleading when classes are imbalanced (rare events).
Precision
"When I say YES, how often am I right?"
High precision = few false alarms. Critical when false positives are costly.
Recall (Sensitivity)
"Of all the real positives, how many did I catch?"
High recall = few missed cases. Critical when false negatives are dangerous.
F1 Score
"What's the balanced score between precision and recall?"
Single number combining both. Best for imbalanced datasets.

The Confusion Matrix

Predicted: PositivePredicted: Negative
Actual: Positive ✔ True Positive (TP)
Correct — caught the case		 ✗ False Negative (FN)
Missed — dangerous in healthcare
Actual: Negative ✗ False Positive (FP)
False alarm — costly in fraud		 ✔ True Negative (TN)
Correct — correctly ruled out

Precision vs. Recall Trade-off

The Core Clinical Trade-off You cannot simultaneously maximize both precision and recall. Raising one typically lowers the other. The right balance depends entirely on which type of error is more costly in your specific domain.
DomainHigh Recall PriorityHigh Precision Priority
Cancer ScreeningMiss as few cancers as possible — a missed diagnosis can be fatal. Accept more false alarms.Only when screening a very large healthy population and follow-up procedures are extremely invasive or expensive.
Fraud DetectionCatch as much fraud as possible — when financial losses from missed fraud exceed the cost of false alarms.When false alarms block legitimate customers — damaging experience and trust.
Spam FilteringCatch more spam — accept some valid email going to the spam folder.Ensure no important email is lost to the spam folder — accept some spam in the inbox.

Cross-Validation & Robustness Testing

📋
Cross-Validation
Split data into multiple folds. Train on most folds, test on the remainder. Repeat. Average results for a more reliable performance estimate than a single train/test split.
🔨
Robustness Testing
Test the model on edge cases, unusual inputs, and adversarial examples. A model that works on clean data may fail on real-world data with noise, missing values, or distribution shifts.
⚖️
Baseline Comparison
Always compare against the simplest possible approach. If your AI barely beats a rule-based system or random guessing, the added complexity may not be worth it.
📉
Survivorship Bias
If your evaluation data only includes successful cases (patients who completed treatment, applications that were approved), your performance estimate is artificially optimistic.
Exam Practice

Section 3.5 — 5 Practice Questions

16. A disease affects 1% of the population. An AI model predicts "No Disease" for every patient and achieves 99% accuracy. What is the PRIMARY problem with using accuracy to evaluate this model?
✔ Correct Answer: B
This is the classic imbalanced dataset problem. A model that never predicts the positive class achieves high accuracy simply because positive cases are rare. The recall for the disease class is 0% — the model is clinically worthless despite high accuracy. Precision and recall are the right metrics here.
Teacher note: This example is deliberately extreme to make the point. Use it to establish the rule: whenever you hear "99% accuracy," ask "what is the class distribution?" before trusting the number.
17. A cancer screening AI flags 100 patients. 30 actually have cancer. 70 were false alarms. What is the model's precision?
✔ Correct Answer: B
Precision = True Positives ÷ (True Positives + False Positives) = 30 ÷ (30 + 70) = 30 ÷ 100 = 30%. Of all patients flagged as having cancer, only 30% actually do. This is a low-precision model — it generates many false alarms.
Teacher note: D is a common student response — they confuse precision (based only on what the model flagged) with recall (which requires knowing the total positive population). Precision needs only the predicted positives.
18. A fraud detection model misses 40% of actual fraud cases but rarely blocks legitimate transactions. Which metric is MOST concerning here?
✔ Correct Answer: B
Missing 40% of fraud cases is a recall problem — the model fails to identify a large proportion of actual positives (real fraud). The problem statement also says it "rarely blocks legitimate transactions," meaning precision is high. The issue is specifically with recall.
Teacher note: D tests whether students can identify what "rarely blocks legitimate transactions" means — that's high specificity (TN rate). The contrast between high precision/specificity and low recall is the key learning here.
19. Which TWO describe appropriate uses of cross-validation? (Choose TWO)
✔ Correct Answers: A and C
Cross-validation gives more reliable performance estimates (A) and reveals performance variance across data splits (C). B misunderstands CV — it still withholds folds for testing. D is a common misconception: cross-validation is used for model selection and validation, not final evaluation. A separate held-out test set is always needed for the final assessment.
Teacher note: D is a critical misconception to correct. Students often think CV eliminates the need for a test set. Clarify: CV uses the training data. The test set is untouched until the final evaluation.
20. A model for predicting hospital readmission achieves excellent results during development but performs poorly after deployment. The team later discovers that post-discharge outcome codes were included as training features. What caused this?
✔ Correct Answer: C
Post-discharge outcome codes are only recorded after the patient is readmitted — they do not exist at the time of prediction. Including them as features gave the model the answer during training. This is data leakage: the model appeared to work because it had access to future information.
Teacher note: A is a common answer because the performance gap resembles overfitting. The distinction: leakage causes the model to succeed on test data too (since the test set also had leaked features). It only fails in production where the future data doesn't exist.
3.6

Identifying & Mitigating Bias in AI Algorithms

"A model that performs equally well for everyone is not just more ethical — it is technically better."

AI bias occurs when a model produces systematically unfair outcomes for certain groups. Bias is rarely intentional — it is almost always inherited from data, design choices, or historical patterns baked into the inputs. Identifying and mitigating it is both an ethical and a technical responsibility.

The 6 Critical Bias Detection Areas

🔎
1. Bias Source Detection
Examine historical data, feature selection, and the algorithm itself for embedded bias before training begins.
📊
2. Input Validation
Verify that incoming real-world data resembles the distribution the model was trained on. Distribution shift causes silent performance degradation.
🔗
3. Correlation Analysis
Detect spurious or proxy variables — features that appear neutral but encode protected characteristics like race, gender, or religion.
⚖️
4. Data Balance Check
Examine class and group representation. Imbalanced training data produces models that perform well for majority groups and poorly for minorities.
🔄
5. Feedback Loop Analysis
Identify self-reinforcing cycles where the AI's decisions create new data that amplifies the original bias.
💬
6. Explainability Check
Ensure decisions can be understood and explained. Opaque models hide bias that might otherwise be obvious.

Three-Stage Mitigation Strategy

StageWhenTechniquesExample
Pre-processing Before training — fix the data Balanced sampling, remove/adjust proxy variables, augment underrepresented groups Oversample minority loan applicants so credit model has equal representation during training
In-processing During training — constrain the model Fairness constraints in the loss function, adversarial debiasing Add a penalty to the fraud model whenever it performs significantly worse on one demographic group
Post-processing After training — adjust outputs Threshold calibration per group, outcome recalibration Set different decision thresholds for different demographic groups to equalize approval rates

Fairness Metrics

Healthcare Bias Examples

Electronic Health Record AI

  • Bias challenge: EHR data reflects historical disparities in care delivery. Certain groups may have received different levels of care — and the AI learns those patterns as if they are medically justified.
  • Pre-processing fix: Remove or adjust features that reflect access to care (e.g., number of prior visits) rather than underlying health status.
  • Monitoring: Track model performance (accuracy, recall) separately for each demographic group after deployment. A model that is 90% accurate overall but 72% accurate for one group has a fairness problem.
Finance Bias Examples

Credit Scoring & Loan Approval

  • Bias challenge: Zip code correlates with race due to historical redlining. A credit model using zip code as a feature may discriminate by proxy even without including race explicitly.
  • Disparate impact testing: Regularly calculate approval and denial rates by demographic group. A statistically significant difference triggers a bias review.
  • In-processing fix: Apply fairness constraints during training that penalize models producing significantly different positive prediction rates across protected groups.

Section 3.6 — 5 Practice Questions

21. A hospital AI for patient triage performs significantly worse for patients over 75 than for younger patients, even though older patients make up 30% of the hospital's population. Which bias detection area should be investigated FIRST?
✔ Correct Answer: B
When a model performs worse for a specific demographic group, the first hypothesis to test is underrepresentation in training data. If the model saw very few elderly patient cases during training, it didn't have enough examples to learn their patterns reliably.
Teacher note: D is plausible in a lending context but not the most logical first step here. Use this to reinforce: bias investigation should follow the evidence — performance gap by age group → data balance first.
22. A bank builds a credit model and removes the "race" and "gender" columns from the training data. A later audit finds the model still denies loans to certain minority groups at disproportionate rates. What is the MOST likely explanation?
✔ Correct Answer: C
Removing protected attribute columns does not prevent discrimination if proxy variables remain. Zip code, neighborhood, and other geographically-linked features can correlate strongly with race due to historical housing discrimination. The model discriminates by proxy.
Teacher note: This is Section 2.3's proxy variable concept applied to Section 3.6. Use it as a deliberate cross-chapter connection point. Fairness is a data problem AND a model problem — both must be addressed.
23. Which bias mitigation approach involves adjusting the model's decision thresholds differently for different demographic groups after training is complete?
✔ Correct Answer: C
Post-processing interventions are applied after the model is trained. Adjusting thresholds — for example, requiring a higher confidence score for one group before making a positive prediction — is a post-processing approach to equalize outcomes across groups.
Teacher note: The three stages map clearly to "before, during, after" training. A clean way to remember: Pre = fix the data, In = constrain the learning, Post = adjust the outputs.
24. Which TWO are examples of feedback loop bias in deployed AI systems? (Choose TWO)
✔ Correct Answers: A and C
Feedback loop bias occurs when the AI's own decisions generate new data that reinforces the original bias (A and C). B describes historical bias — the bias exists in the data before the AI was deployed. D describes underrepresentation bias — a data collection issue, not a deployment feedback effect.
Teacher note: B and D are traps because they involve bias, just not feedback loop bias. Use this to reinforce the taxonomy: historical bias, representation bias, feedback loop bias — different causes, different solutions.
25. What does "equal opportunity" mean as a fairness metric for AI systems?
✔ Correct Answer: B
Equal opportunity means that among individuals who deserve a positive outcome (truly qualified loan applicants, truly sick patients), the model identifies them at the same rate across all groups. A describes demographic parity — a different metric. C and D describe training data balance and accuracy parity respectively.
Teacher note: A (demographic parity) is often confused with equal opportunity. The key distinction: demographic parity looks at all predictions; equal opportunity looks only at the truly positive cases. These lead to different interventions.
