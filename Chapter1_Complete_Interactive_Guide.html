🎬 Opening Hook — Use This to Open Class

Imagine you're a doctor. Before prescribing medicine, you diagnose the problem first — is it a bacterial infection? A broken bone? You wouldn't give antibiotics for a fracture. The tool isn't wrong. The diagnosis is wrong.

AI works the same way. Before building any AI solution, you must first define what problem you're solving. Get this wrong and it's like using a surgical robot to diagnose a common cold. In business terms: wasted resources, failed projects, and costly digital paperweights. The book's core message: "the most valuable skill is knowing when AI is — and isn't — the answer."

Q 01
A hospital wants AI to automatically sort ER patients by urgency. Which BEST describes this type of AI problem?
▾
  • AA regression problem, because the system predicts a continuous severity score
  • BA classification problem, because the system sorts patients into defined priority categories
  • CA reinforcement learning problem, because the system learns by trial and error
  • DAn unsupervised learning problem, because patient data has no labels
✅ Correct Answer: B
The system places each patient into one of pre-defined, labeled categories (Critical, Urgent, Standard, Non-urgent). Any time you sort into known categories, that is a classification problem. Regression outputs a continuous number. Reinforcement learning uses trial-and-error rewards. Unsupervised learning is for when no labels exist upfront.
Ask: "What would the inputs be?" Expected: vitals, symptoms, age, arrival time. This connects to Input/Output Analysis — the 3rd critical question.
Q 02
A project manager writes: "We want AI to improve customer service." According to the Problem Identification framework, what is the PRIMARY issue with this statement?
▾
  • ACustomer service is not a valid domain for AI applications
  • BThe statement is too vague and lacks measurable, specific outcomes
  • CThe problem requires reinforcement learning, which is too advanced
  • DThe problem does not include enough input data sources
✅ Correct Answer: B
The framework requires clear, specific, measurable problem definitions — ideally one sentence. "Improve customer service" cannot be built upon, measured, or scoped. The correct version: "Reduce wait times for simple inquiries from 10 minutes to 2 minutes."
Classroom exercise: Ask students to rewrite this as a proper one-sentence problem statement using the framework. Give 90 seconds, then share.
Q 03
An IT team recommends NOT using AI to auto-total daily sales figures. Which reason from the framework BEST justifies this?

  • BThe problem involves too much data for AI to process

  • DAI systems cannot work with sales data
✅ Correct Answer: C
The "AI-Not-Needed" red flag: can the problem be solved with simple rules or arithmetic? Adding numbers is deterministic — there's nothing to learn, no patterns to find. The framework reason is always about problem suitability first, not budget or technical limits.
Exam trap: Budget (A) sounds correct but is a business constraint, not the framework reason. Train students to filter through suitability first.

Section 1.2
AI Problem Classification
The 4 Main Types · Supervised vs Unsupervised · Decision Framework · Real-World Examples
🩺 Opening Analogy

Imagine you're a doctor treating a patient. Is it a bacterial infection (antibiotics), a broken bone (cast), or a chronic condition (lifestyle change)? Before prescribing anything, you classify the problem type — because the classification determines everything: what treatment to use, how to measure success, and even whether your intervention will work.

AI works the same way. Getting the problem classification wrong is like using a hammer to tighten a screw — disastrous results with the wrong tool. In business: wasted resources, failed projects, missed opportunities.

Supervised Learning

1. Classification

You have labeled examples. The AI learns to sort new things into one of the predefined categories.

Analogy: Showing a child pictures labeled "dog" and "cat" until they can identify new animals
Healthcare: Is this tumor malignant or benign?
Finance: Is this transaction fraudulent or legitimate?
Supervised Learning

2. Regression

You have labeled examples with numerical outputs. The AI learns to predict a specific number.

Analogy: Learning to estimate house prices by studying thousands of homes with known prices
Healthcare: Predict a patient's blood sugar level in 6 months
Finance: Predict tomorrow's stock price or loan default risk score
Unsupervised Learning

3. Clustering / Grouping

You have data but NO labels or correct answers. The AI discovers hidden patterns and natural groupings on its own.

Analogy: Giving a child a box of mixed toys and asking them to organize the groups themselves
Healthcare: Group patients with similar symptoms to find unknown disease sub-types
Finance: Segment customers by spending behavior without predefined categories
Reinforcement Learning

4. Reinforcement Learning

The AI learns by trying actions and receiving rewards or penalties. No labeled data — the AI learns from consequences.

Analogy: Teaching a dog tricks using treats (reward) and no treats (penalty)
Healthcare: AI adjusting insulin doses for diabetic patients, learning from glucose responses
Finance: Algorithmic trading — AI making trades, learning which strategies maximize returns
🔑 The Key Decision Question

Ask yourself one question first: "Do I know the correct answer for my existing examples?"

→ YES — you have labeled data → You likely have a Supervised Learning problem (Classification if output is a category, Regression if output is a number)
→ NO — no labels exist → You likely have an Unsupervised Learning problem (discover patterns)
→ You want an agent to make sequential decisions and learn from rewards → Reinforcement Learning

Healthcare · Classification

Cancer Detection from Mammograms

ProblemAI reviews mammogram images and determines whether tissue is cancerous or normal
Why Classification?Output is a category — "Malignant" or "Benign." The AI has thousands of labeled training images from confirmed diagnoses
Real ImpactA 2020 Nature study found AI detected breast cancer more accurately than two radiologists reviewing the same images
✅ Classification — Labeled data, categorical output (malignant / benign)

Patient Subtype Discovery

Why Unsupervised?No predefined labels exist. The AI discovers natural clusters in patient data — researchers may find 3 disease subtypes they didn't know existed
Real ImpactEnabled personalized treatment approaches for different cancer subtypes, improving survival rates
🔶 Unsupervised — No labels, AI discovers unknown groupings
Finance · Classification

Email Spam / Fraud Flagging

ProblemAI flags whether incoming emails or transactions belong to one of two categories: legitimate or fraudulent
Why Classification?Output is a binary category. Thousands of labeled past examples (confirmed fraud vs confirmed legitimate) train the model
Example FlowGather labeled examples → Identify features (amount, location, time) → AI learns patterns → Classify new transactions in <300ms
✅ Classification — Binary categorical output, labeled training data available
Finance · Regression

Stock Price Prediction

ProblemPredict tomorrow's closing price for a given stock based on historical data and market indicators
Why Regression?Output is a continuous number (e.g., "$182.50"). Historical prices with known outcomes serve as labeled training data
InputsHistorical prices, trading volume, news sentiment, economic indicators, competitor performance
🔶 Regression — Continuous numerical output, historical labeled data
🗂 Step-by-Step Decision Framework

Step 1 — Look at your data: Do you have labels (correct answers) for your examples?
Step 2 — Examine your output: Is it a category? → Classification. Is it a number? → Regression. Unknown groups? → Unsupervised. Sequential decisions? → Reinforcement Learning.
Step 3 — Define success: For classification: what's worse — missing a positive case (false negative) or a false alarm (false positive)? For regression: what's an acceptable margin of error?

Common Pitfall

Confusing Classification with Regression

MistakeBuilding a regression model when you needed classification — e.g., predicting "79% fraud probability" when you just need Approve/Decline
Why It MattersWrong problem type → wrong algorithm → wrong evaluation metrics → system fails in production
FixAlways define your output type first: category or number? That single answer determines your problem type
🚫 Misclassifying the problem type invalidates everything downstream
Section 1.2 · Exam Questions
🎯

5 exam-style questions for Section 1.2. Cover all four problem types. Common exam trap: distinguishing classification from regression, and supervised from unsupervised.

Q 06
An AI system predicts tomorrow's stock price as a specific dollar amount (e.g., $182.50). Which type of AI problem is this?
▾
  • AClassification, because the AI is making a decision about the stock
  • BRegression, because the AI is predicting a continuous numerical value
  • CUnsupervised learning, because stock patterns are unknown
  • DReinforcement learning, because the AI learns from market rewards
✅ Correct Answer: B
Regression is used whenever the AI must output a continuous numerical value — like a price, temperature, or probability score. Classification outputs a category (buy/sell/hold). The output type is the deciding factor: number → regression, category → classification.
Memory tip: "Regression = Real numbers. Classification = Categories." Have students repeat this.
Q 07
A marketing team gives an AI system customer purchase data with NO predefined customer segments. The AI discovers three natural groups: bargain hunters, brand loyalists, and impulse buyers. Which type of AI problem is this?
▾
  • AClassification, because the customers end up in categories
  • BRegression, because customer lifetime value is being predicted
  • CUnsupervised learning, because no predefined labels existed before the AI discovered the groups
  • DReinforcement learning, because the AI improved by receiving customer feedback
✅ Correct Answer: C
Unsupervised learning is defined by the absence of predefined labels. The team did not tell the AI what groups exist — the AI discovered them. The book's analogy: "Giving a child a box of mixed toys and asking them to organize the groups themselves." The result may include categories, but the process uses no labeled training data.
Exam trap: Option A sounds appealing because the output IS categories. The key distinction is whether labels existed BEFORE training. If yes → supervised classification. If no → unsupervised.
Q 08
A hospital AI analyzes thousands of mammogram images that have been reviewed and labeled by radiologists as "cancerous" or "normal." The AI learns to identify cancer in new images. Which type of AI problem is this?
▾
  • ASupervised learning — classification, because labeled training data and categorical output exist
  • BUnsupervised learning, because the AI must discover patterns in medical images
  • CReinforcement learning, because the AI learns from patient outcomes over time
  • DSupervised learning — regression, because cancer severity is measured on a scale
✅ Correct Answer: A
Two conditions confirm supervised learning — classification:
1. Labeled training data exists (radiologists confirmed "cancerous" or "normal" for each image)
2. Output is a category (cancerous / normal), not a continuous number

D is wrong because regression would output a number like "37% cancer probability" — this scenario outputs a discrete category.
This mirrors the real-world example from the book: Google's AI detecting diabetic retinopathy from eye scans — labeled by ophthalmologists, output is a diagnosis category.
Q 09
Which of the following BEST describes the key difference between supervised and unsupervised learning?
▾
  • ASupervised learning uses more data than unsupervised learning
  • BSupervised learning trains on labeled examples with known correct answers; unsupervised learning discovers patterns in unlabeled data
  • CSupervised learning is faster and cheaper to implement
  • DUnsupervised learning requires human oversight; supervised learning does not
✅ Correct Answer: B
The defining characteristic is the presence or absence of labels. Supervised = "answer key exists" (like a teacher grading homework). Unsupervised = "no answer key — find the patterns yourself" (like sorting a mixed box of objects by your own logic). Amount of data, speed, and cost vary by context and do not define the type.
Analogy from class notes: "Answer key vs. sorting unknown coins." Write this on the board. Students consistently find this memorable for exam recall.
Q 10
A pharmaceutical company wants AI to learn which drug combinations produce the best patient outcomes by testing combinations and observing results over time — without pre-labeled training data. Which problem type BEST describes this?
▾
  • AClassification, because outcomes are categorized as effective or ineffective
  • BRegression, because effectiveness is measured as a numerical score
  • CUnsupervised learning, because no labeled data exists
  • DReinforcement learning, because the AI learns from the consequences of its actions (drug combinations) over time
✅ Correct Answer: D
Reinforcement learning is defined by: (1) an AI agent that takes sequential actions, (2) receives rewards or penalties based on outcomes, and (3) learns to maximize positive outcomes over time — with no pre-labeled dataset. The book's analogy: "Teaching a dog tricks using treats." The drug company setup matches all three conditions.
Reinforce: RL is less common in the certification than supervised/unsupervised, but appears in tricky questions. The key markers are: agent + actions + rewards over time.
Section 1.3
Identifying Areas of Expertise for AI Projects
The 4 Expertise Types · Why Each Matters · Common Mistakes · Healthcare & Finance Examples
🏥 Opening Story

A hospital wants AI to detect cancer in X-rays. They hire a brilliant team of machine learning engineers. The AI works — technically. But it recommends treatments that violate hospital drug protocols and doesn't account for insurance coverage constraints. The AI team had no idea. Nobody asked a doctor, a compliance officer, or an IT architect to join the project.

The book's lesson: In today's world, AI isn't just about algorithms. It requires a diverse team that bridges what's technically possible and what's actually useful in the real world. The difference between projects that succeed and those that fail often comes down to one factor: having the right expertise in the room from day one.

Type 1

Business Expertise

Understanding the organization's goals, constraints, regulations, and risk management. Defines what "success" means for the organization — not just for the model.

👤 Who: Business analysts, product managers, compliance officers, executives
Type 2

Domain (Subject-Matter) Expertise

Deep knowledge of the specific field the AI operates in. Without this, the AI may be technically correct but clinically or financially meaningless.

👤 Healthcare: Doctors, nurses, pharmacists. Finance: Loan officers, risk analysts, traders
Type 3

AI Expertise

Knowledge of machine learning algorithms, model training, evaluation metrics, and data pipelines. Knows which algorithm fits which problem type.

👤 Who: Data scientists, ML engineers, AI researchers, statisticians
Type 4

Implementation Expertise

Skills needed to deploy and maintain the AI system in real-world production. Bridges the gap between a model in a notebook and a system that runs in a hospital or bank 24/7.

👤 Who: Software engineers, DevOps, cloud architects, IT security specialists
Healthcare

AI System: Cancer Detection in Medical Imaging

BusinessHospital leadership defines ROI targets, patient safety requirements, liability limits, and regulatory compliance with FDA and HIPAA
DomainRadiologists label training images, define what "suspicious" means clinically, flag edge cases the AI must handle correctly
AIData scientists select a CNN (convolutional neural network), train on labeled scans, evaluate with sensitivity/specificity metrics
ImplementationEngineers integrate AI with hospital PACS (imaging system), ensure DICOM format compatibility, deploy with 99.9% uptime SLA, monitor for model drift
✅ All 4 expertise types required — missing any one causes project failure
Finance

AI System: Credit Risk Assessment

BusinessRisk management defines acceptable default rates, profit margins, regulatory constraints (Fair Credit Reporting Act, Equal Credit Opportunity Act)
DomainExperienced loan officers provide insight into which features actually predict default; flag proxy variables that could cause illegal discrimination
AIML team selects gradient boosting model, trains on historical loan data, evaluates with precision/recall, tunes for the right false-positive/negative tradeoff
ImplementationEngineers deploy to production loan system, ensure <200ms response time for real-time decisions, build audit logging for regulatory review
✅ Each expertise type adds irreplaceable value — especially regulatory/domain expertise in finance
MISTAKE 01

Assuming AI Expertise Is Enough

Teams hire data scientists and build technically correct models that solve the wrong business problem. The model runs perfectly — but recommends something the organization would never do.

MISTAKE 02

Forgetting Implementation

Building a beautiful model in a notebook that can never be deployed. No API, no integration, no monitoring. The project dies at the handoff from data science to engineering.

MISTAKE 03

Ignoring Regulatory Requirements

In healthcare and finance, strict laws govern AI use. Teams that don't include compliance experts early discover (often too late) that their system violates HIPAA, Fair Lending laws, or FDA guidelines.

MISTAKE 04

Underestimating Data Expertise

Domain experts must be involved in labeling training data and validating outputs. A radiologist who labels "suspicious" areas is as important as the ML engineer who trains the model.

Section 1.4
AI Security Planning
Why AI Has Unique Vulnerabilities · 4 Attack Types · Access Control · Healthcare & Finance Risks · Security Plan Phases
⚠️ Opening Hook

Imagine a hacker who tricks a hospital's AI into misdiagnosing cancer — not by breaking into the database, but by adding invisible pixel changes to an X-ray image that fool the AI while looking completely normal to a doctor. Or a competitor who quietly corrupts the training data for a bank's fraud detection system, teaching it to approve fraudulent transactions.

AI Has Unique Vulnerabilities unlike traditional software. You can't just install a firewall. The attack surface includes the data, the model, the inputs, and even the outputs. Security is not optional — it must be built in from the very beginning, not added later.

🔑 What Is AI Security Planning?

The process of identifying, assessing, and protecting against threats that could compromise AI systems. Think of it as building a fortress around your AI — with different gates for different types of threats: internal access, external attacks, data integrity, and infrastructure protection.

Attack Type 1

Adversarial Attacks

Tiny, invisible changes to input data that fool the AI while appearing normal to humans. Example: imperceptible pixel changes to an X-ray that make a tumor appear benign.

Input validation, multiple model verification, anomaly detection for unusual inputs
Attack Type 2

Data Poisoning

Corrupting the training data to make the AI learn wrong patterns. Example: injecting fraudulent-labeled-as-legitimate transactions into training data to teach fraud detection to approve fraud.

Data validation and provenance tracking; secure, audited training pipelines
Attack Type 3

Model Extraction

Stealing an AI model by repeatedly querying it and reverse-engineering its behavior. Example: a competitor rebuilds your proprietary credit scoring model through API calls.

Rate limiting on API queries; output obfuscation; query monitoring and anomaly alerts
Attack Type 4

Privacy Attacks

Extracting sensitive personal information from AI models. Example: a model trained on patient records may "memorize" and inadvertently reveal private patient data when queried.

Differential privacy techniques; output filtering; minimum query thresholds
Access Control — The "Least Privilege" Principle
🔑 Analogy: Different Keys for Different Rooms

Think of this as creating different "keys" for different people in your organization. A nurse might only need Level 2 access (view recommendations and patient data). A senior radiologist needs Level 3 (modify treatment plans). A system administrator needs Level 4 (modify AI model parameters). The Principle of Least Privilege: give each person only the minimum access they need to do their job — nothing more.

Security Plan: 4-Phase Implementation
P1

Assessment (Weeks 1–2)

Inventory all AI assets (models, data sources, infrastructure). Identify threat vectors. Classify data sensitivity. Map who currently has access to what.

P2

Planning (Weeks 3–4)

Design access control levels. Define authentication requirements. Plan adversarial testing strategy. Document infrastructure security requirements.

P3

Implementation (Weeks 5–8)

Deploy role-based access control. Implement input validation and anomaly detection. Harden infrastructure. Conduct adversarial penetration tests.

P4

Monitoring & Maintenance (Ongoing)

Continuous monitoring for unusual query patterns. Regular security audits. Update defenses as new attack methods emerge. Incident response drills.

Access ControlNurses: view recommendations only. Radiologists: view + annotate. Senior physicians: modify treatment plans. IT admins: model configuration. All with audit logs.

Section 1.4 · Exam Questions
Q 15
A researcher adds tiny, invisible changes to X-ray images that cause an AI system to misclassify tumors as benign. These changes are undetectable to human radiologists. Which type of AI attack does this describe?
▾
  • AAn adversarial attack, because subtle input manipulation causes the AI to produce incorrect outputs
  • BA data poisoning attack, because training data is being corrupted
  • CA model extraction attack, because the attacker is accessing the AI model
  • DA privacy attack, because patient data is being accessed without consent
✅ Correct Answer: A
Adversarial attacks manipulate input data at inference time (when the model is making predictions) — not during training. The key marker: changes are made to live inputs (the X-ray being analyzed), not to training data. Data poisoning (B) targets the training process, not live inputs. The book's exact example matches this scenario precisely.
Exam distinction: Adversarial = attack on live inputs. Poisoning = attack on training data. Both are attacks, but at different stages of the AI lifecycle.
Q 16
A financial institution discovers that its AI fraud detection model has been approving certain fraud patterns that it used to catch. Investigation reveals that someone injected mislabeled examples into the training dataset. Which attack type occurred?
▾
  • AAn adversarial attack
  • BA data poisoning attack
  • CA model extraction attack
  • DA privacy attack
✅ Correct Answer: B
Data poisoning specifically involves corrupting the training dataset so the AI learns wrong patterns. The attacker injected mislabeled fraud examples into training data — teaching the model that certain fraud patterns are legitimate. This is distinct from adversarial attacks, which manipulate live inputs after training. Defense: secure, audited training data pipelines with data provenance tracking.
Key phrase for students: "If the attack happened BEFORE training → Data Poisoning. If it happened AFTER training on live inputs → Adversarial Attack."

  • BPrinciple of Least Privilege
  • CDefense in Depth
  • DSecurity by Obscurity
✅ Correct Answer: B
The book describes this as: "Give each person only the minimum access they need to do their job — nothing more." A nurse might only need Level 2 (view AI recommendations). A senior physician needs Level 3 (modify treatment plans). A system admin needs Level 4 (configure the model). This limits the damage any single compromised account can cause.
Real-world anchor: Most healthcare data breaches don't come from hackers — they come from employees accessing more data than their role requires. Least Privilege directly prevents this.
Q 18
The book states: "Security is not optional — it must be built in from the start, not added later." Which phase of the AI Security Planning framework addresses this by inventorying all AI assets and identifying threat vectors?
▾
  • APhase 1: Assessment
  • BPhase 2: Planning
  • CPhase 3: Implementation
  • DPhase 4: Monitoring
✅ Correct Answer: A
Phase 1 (Assessment) is the foundation: inventory all AI assets, data sources, and infrastructure; identify all possible attack vectors; classify data sensitivity; map existing access permissions. This is what "building security in from the start" means operationally. Without this inventory, you cannot plan, implement, or monitor effectively.
Security phases follow a logical order that students sometimes mix up. Teach it as: "You can't protect what you haven't identified. Assessment always comes first."
Section 1.5
AI Ethics & Responsible AI Implementation
Why Ethics Matters · Core Components · Real Failures · Guidelines · Preventing Harm
🌍 Opening Story

Imagine a world where AI systems make decisions that affect millions of people daily — who gets a loan, who gets hired, who gets medical care. This is happening right now. And when those systems go wrong, real people pay real prices.

Amazon built an AI to screen resumes. It was technically brilliant. But it learned from 10 years of hiring data, during which the company had hired mostly men. The AI learned: "resumes that look like past hires = good." It began downgrading resumes that contained the word "women's." Amazon scrapped it entirely.

AI ethics isn't about being "nice." It's about ensuring that AI systems work fairly for everyone and don't cause real harm to people's lives.

⚖️

Fairness

AI decisions must not discriminate based on race, gender, age, or other protected characteristics. Equal treatment doesn't always mean fair treatment.

🔍

Transparency

People affected by AI decisions should be able to understand how those decisions were made. "Black box" systems that can't be explained raise serious ethical concerns.

🎯

Accountability

Someone must be responsible for the AI's decisions and their consequences. "The algorithm decided" is not an acceptable answer when harm occurs.

🌱

Beneficence

AI should genuinely benefit the people it affects — not just the organization deploying it. The goal is technology that improves lives equitably.

🚫

Non-Maleficence

AI should not cause harm, even unintentionally. This includes indirect harm through biased decisions, privacy violations, or misuse of outputs.

🔒

Privacy

Individuals have the right to control their personal data. AI systems must be designed to protect privacy, not exploit it.

📊 Data Gathering Guidelines

Ensure training data represents all people the AI will affect — not just the majority
Don't use data from only one hospital, region, or demographic
Regularly test for statistical bias across demographic groups
Document where data came from and what populations it represents

🚫 Preventing Out-of-Context Use

An AI designed for one job role should never be applied to a different role without revalidation
Document the intended use case and prohibit unauthorized applications
Regularly audit whether the AI is being used for its intended purpose
Provide clear explanations to users of what the AI can and cannot appropriately decide
S1

Pre-Development Assessment

Who will this AI affect? Could it cause harm to vulnerable groups? What data will it use, and does that data fairly represent everyone?

S2

During Development

Test for bias across demographic groups at every stage. Choose explainable algorithms where human oversight is required. Document every data and design decision.

S3

Before Deployment

External ethics review. Legal compliance check. Simulate edge cases and vulnerable group scenarios. Define the escalation path when the AI is wrong.

S4

Post-Deployment Monitoring

Track performance across demographic groups continuously. Create clear appeal processes for affected individuals. Set triggers for retraining if bias patterns emerge.

Section 1.5 · Exam Questions
Q 19
Amazon built an AI resume screening system trained on 10 years of hiring data. The system began downgrading resumes containing the word "women's." Which type of AI bias does this BEST illustrate?
▾
  • AAdversarial bias, because an attacker manipulated the input data
  • BHistorical bias in training data, because the AI learned and perpetuated past discriminatory hiring patterns
  • CModel extraction bias, because competitors accessed the hiring model
  • DImplementation bias, because the deployment team made errors
✅ Correct Answer: B
The book describes this directly: "The historical data shows that the company previously hired mostly men. The AI learns this pattern and starts automatically ranking men higher." No attacker was involved — the AI correctly learned from its training data. The data itself encoded historical discrimination, and the AI amplified it. This is the most common and insidious form of AI bias.
Key insight: The AI was doing exactly what it was designed to do — learn patterns from data. The ethical failure happened at the data selection and problem definition stage, not the algorithm stage.
Q 20
A hospital's AI diagnostic system was trained primarily on data from wealthy, insured urban patients. When deployed in a diverse community hospital, it consistently underestimates urgency for underinsured patients. Which ethical principle is MOST violated?
▾
  • AFairness, because the AI produces inequitable outcomes for different patient populations
  • BTransparency, because the AI cannot explain its decisions
  • CPrivacy, because patient data is being misused
  • DAccountability, because no one reviewed the AI's decisions
✅ Correct Answer: A
Fairness — the AI produces systematically worse outcomes for underinsured patients than for insured patients, based solely on who was represented in the training data. The book calls this a violation of equitable care: "Patients who need urgent care are deprioritized, potentially leading to worse health outcomes." The fix: ensure training data represents the full spectrum of patients the AI will encounter.
Connect to Section 1.3: this is also an expertise failure — domain experts (diverse clinicians) were not consulted during data selection, which is exactly Mistake #2 from the expertise section.
Q 21
A credit scoring AI uses ZIP code as one of its input features. A fairness audit reveals that in practice, applicants from certain ZIP codes — which correlate highly with racial demographics — are being denied loans at much higher rates. This is an example of which ethical issue?
▾
  • AData poisoning, because the training data was corrupted
  • BProxy variable discrimination, because a seemingly neutral feature encodes a protected characteristic
  • CModel extraction, because the credit model is being reverse-engineered
  • DAdversarial attack, because applicants are manipulating their ZIP codes
✅ Correct Answer: B
Proxy variable discrimination occurs when a feature that appears statistically neutral (ZIP code) actually acts as a stand-in for a protected characteristic (race/ethnicity). The AI isn't explicitly using race — but it achieves the same discriminatory outcome because of the correlation. This violates the Equal Credit Opportunity Act and is one of the most common and legally dangerous ethics issues in financial AI.
Important legal note: Intent doesn't matter in discrimination law. If the outcome is discriminatory — even due to a proxy — it can be illegal. This is why fairness audits are mandatory in financial AI.
Q 22
According to the book's Responsible AI guidelines, when choosing between a highly accurate "black box" algorithm and a slightly less accurate algorithm that can explain its reasoning, which should a medical AI system use and why?
▾
  • AThe black box algorithm, because accuracy is always the top priority in healthcare
  • BThe explainable algorithm, because doctors must be able to review, understand, and override AI recommendations
  • CThe black box algorithm, because patients don't need to understand AI decisions
  • DEither is acceptable, because both produce good outcomes
✅ Correct Answer: B
The book states: "For a medical diagnosis AI, choose an algorithm that can explain its reasoning to doctors, even if a more complex 'black box' algorithm might be slightly more accurate." In high-stakes domains like healthcare, transparency and human oversight are more important than marginal accuracy gains. Doctors must be able to understand, evaluate, and override AI recommendations — they remain legally and medically responsible for every decision.
This is a values question disguised as a technical question. Train students to recognize when ethics principles (transparency, accountability) override pure performance metrics.
Q 23
A company builds an AI system to assess software engineers' technical skills. The HR department wants to also use it to screen customer service candidates. According to the book's Responsible AI guidelines, why is this problematic?
▾
  • AUsing AI for customer service screening is illegal under data privacy laws
  • BThe AI would need to be retrained with more data before it could be used for any purpose
  • CThe skills and success patterns for software engineers are different from those for customer service roles, making the AI's learned patterns irrelevant and potentially harmful in the new context
  • DCustomer service roles don't generate enough data for AI screening
✅ Correct Answer: C
The book explicitly warns against out-of-context use: "An AI system designed to screen resumes for software engineering positions shouldn't be used to screen candidates for sales positions, as the skills and requirements are completely different." The AI learned what makes a successful software engineer. That pattern does not transfer to customer service — applying it would unfairly penalize perfectly qualified candidates.
This is a governance and ethics failure that happens most often after a successful AI deployment — teams expand use cases beyond the original scope without revalidating. Build this awareness explicitly.
Q 24
The book states that when a loan application is denied by an AI, the applicant has a right to know why. Which ethical principle does this MOST directly reflect?
▾
  • ANon-maleficence
  • BFairness
  • CTransparency
  • DBeneficence
✅ Correct Answer: C
Transparency — the principle that people affected by AI decisions should be able to understand how those decisions were made. The Fair Credit Reporting Act in the US requires that denied applicants receive a specific human-understandable explanation. "The algorithm said no" violates both the ethical principle of transparency and the legal requirement for explainability in financial decisions.
Connect to the Certiport exam theme: ethics principles map to real laws. Transparency → FCRA, GDPR right to explanation. Fairness → Equal Credit Opportunity Act. Privacy → HIPAA, GDPR. Students should know these connections.
Q 25
Which of the following BEST describes a "feedback loop bias" in AI systems?
▾
  • AWhen an AI system learns more slowly because of poor-quality feedback data
  • BWhen users deliberately provide incorrect feedback to manipulate the AI
  • CWhen AI decisions create conditions that reinforce the original bias — the AI's outputs become the next generation's training data
  • DWhen AI accuracy degrades over time due to outdated training data
✅ Correct Answer: C
The book defines this as: "When AI decisions create conditions that reinforce the original bias." Example: an AI denies loans to certain neighborhoods → those neighborhoods have lower economic activity → that data is used to retrain the model → the model learns those neighborhoods are higher risk → denies even more loans. The AI's own decisions become the evidence for its future decisions, compounding the original bias exponentially.
This is the most sophisticated bias concept in Chapter 1 and typically appears in more advanced exam questions. Anchor it with the COMPAS recidivism example: AI predicts reoffending → person is incarcerated longer → more likely to encounter criminal justice system → confirms the prediction.
